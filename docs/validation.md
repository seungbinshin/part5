- 원강의, 공개 문서의 보완, 새 합성 실습과 편집 판단을 구분했다. 참고 강의의 토큰·레이아웃을 참고해 화면 코드는 새로 작성했다.

## 실습 검사

`python3 practice/smoke_test.py`: 6개 통과. 정상 결과, 누락된 주장, 잘못된 일반화, 입력 변경, 허용 범위 밖 쓰기 선언, 승인 완료 사칭을 검사했다.

`python3 practice/test_upgrade.py --part4-reference <Part4-참조폴더> --actual-wiki-root <기존-Wiki-폴더>`: 16개 통과. Part 4 배포 구조와 실제 기존 Wiki의 필요한 선행 파일을 **임시 사본으로만** 복사해 검사했다. 운영 Wiki에는 적용하지 않았다.

- 계획 → 추가 → 원복 후 기존 파일 보존
- 잘못된 경로·심볼릭 링크·기존 폴더·선행 자료 누락 거부
- 계획 이후 기존 파일 변경, 변조된 manifest 거부
- `apply --dry-run`이 쓰기를 하지 않고 오류로 끝남
- 사용자가 추가한 보고서 보존, 변경된 추가 파일이 있으면 원복 전체 중단
- 파일·manifest의 부분 쓰기, 최종 이동 실패, 중간에 생긴 사용자 폴더 등 4개 오류 주입 검사

부분 쓰기 문제를 독립 검토에서 발견해 임시 폴더에서 완성·검증 후 이동하도록 수정했다. 수정 후 오류 주입 4개를 독립 재실행해 통과했다. 이 검사는 일반적인 동시 공격이나 운영체제 권한 격리를 보장하지 않는다.

## 세 사례로 제한한 로컬 추가본 검증

같은 확인일의 최신 요청에 따라 GPU CCWS·SWL, HexaHarness, DRAM ATLAS 세 사례만 남겼다. 이 절의 검증 대상은 강의안과 사례 요약이며 원본 프로젝트의 재실행 결과가 아니다.

- 배포 데이터·생성 HTML에 정확히 세 사례만 존재한다. 나머지 조사 자료는 저장소 밖 로컬에 보존한다. 숨긴 추가 카드·검색·필터·더 보기와 해당 JS 처리도 제거했다.
- 독립 편집·민감정보 검토와 im-not-ai 텍스트 규칙으로 윤문했다. GPU는 과거 사용자 보고, HexaHarness는 당시 세 운영체제 설치·시험과 실제 모델 품질 미측정, ATLAS는 교육 모델·실제 장비/규격 검증과의 구분 및 당시 최종 브라우저 QA 미확인을 명시했다.
- `python3 build.py --require-project-cases` 통과. 원문 해시 8개를 보존했다. 기존 강의 article 7개·실습 파일·전사문은 기존 게시 기준 커밋 `e347e3c`와 동일하다.
- `python3 -m unittest discover -s tests -v`: 12개 통과. 정확히 세 개 제한, 선정 ID, 모두 보이는 세 카드와 불필요 제어의 부재, 미검토·빈 데이터 거부, HTML 이스케이프, 잘못된 입력에서 출력 보존을 검사했다.
- 기존 실습 검증 6개와 위키 사본 업그레이드 검사 16개를 다시 통과했다. Part 4 참조와 실제 Wiki의 선행 파일을 임시 사본으로만 읽어 사용했으며 운영 Wiki에 적용하지 않았다.
- 별도 로컬 IAB 탭에서 1440×900과 390×844를 확인했다. 세 카드의 키보드 펼침·접힘, 세 탭 방향키·Home·End, 용어 설명·Escape, 코드 복사 일치, 기존 세 문제 정답·초기화를 검사했다.
- 모바일 8개 경로에서 주제 하나씩 표시됐고 문서 너비는 모두 390px였다. 목차 열기·Escape·포커스 복귀도 확인했다. 관찰한 콘솔 경고·오류는 없었다. 실제 휴대전화 터치 센서는 시험하지 않았다.

## 실행하지 않은 항목

실제 모델 호출·결제·새 인증·긴 훈련·운영 Wiki 갱신은 수행하지 않았다. 모델 응답 품질, 비용, 지연, 학습 시간과 연구 생산성 개선은 측정하지 않았다. 예상 학습시간과 사전 작성 답은 각각 그 사실을 표시했다.

GitHub 저장소 게시와 웹 호스팅은 별개다. 이번 추가본의 원격 게시와 Pages 구성은 수행하지 않았다.
