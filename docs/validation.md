초기 제작에서는 실제 모델 호출·결제·새 인증·긴 훈련·운영 Wiki 갱신을 수행하지 않았다. 후속 프롬프트 개편의 AI 코딩 도구 실행은 아래에 따로 기록한다. 모델 응답 품질, 비용, 지연, 학습 시간과 연구 생산성 개선은 측정하지 않았다. 예상 학습시간과 사전 작성 답은 각각 그 사실을 표시했다.

## 자기 프로젝트용 프롬프트 개편

핵심 실습을 세 번의 프롬프트 전달로 구성했다. 처음에 프로젝트와 강의 자료 경로를 지정하고 같은 대화에서 이어간다. 경로가 분명하지 않거나 근거가 없을 때의 질문, 도구 권한 승인, 연구자의 최종 판단은 남는다. 세 번만으로 모든 환경에서 완료된다는 보장은 아니다.

실제 AI DRAM Wiki의 적용 전후는 [별도 예시](wiki-applied-example.md)로 정리했다. 로컬 커밋과 당시 Python 78개·JS 4개·결함 주입 15개 검사 기록을 읽기 전용으로 교차 확인했으며, 이번 강의 개편에서 그 Wiki 검사를 재실행하지 않았다. 운영 게시나 실제 GPU·DRAM 측정 결과가 아니다.

### 핵심 프롬프트를 실제로 따라간 범위

서로 다른 새 AI 작업 컨텍스트에서 핵심 프롬프트 세 개를 순서대로 실행했다. 공개 Part 4 템플릿·Skill에 공개 논문 해설과 의도적인 잘못된 주장 세 개를 넣은 테스트 프로젝트를 사용했다. 실제 학습자의 전체 프로젝트나 비공개 연구 자료를 검증한 것은 아니다.

| 시작 구조 | 실제 결과 |
|---|---|
| `.agents/skills/` + `llm_wiki/research/` | 기존 경로를 따른 사본·근거표·미실행 계획·초안·역할 계약·검토·인계·작은 검사기 생성 |
| `skills/` + `research/` | 다른 경로를 유지하며 같은 목적의 산출물 생성. 강의의 고정 실습 폴더나 Wiki 스키마를 이식하지 않음 |

- 두 경로 모두 실제 산출물 검사 PASS(종료 코드 0), 근거 연결 누락과 낡은 해시의 임시 복제 입력은 각각 FAIL(1)이었다. 기본 구조의 해시 결함 입력 준비에서 불필요한 복제본 소유 목록을 한 번 바로잡았고, 최종 실패가 해시 불일치에서 발생하는지 확인했다.
- 두 원본과 각 사본의 기존 11개 파일을 기준 해시와 직접 대조해 모두 보존됐음을 확인했다. 검토는 각 실행의 같은 컨텍스트에서 진행했으며 독립 심사로 표시하지 않았다.
- 다른 구조에서 2단계 프롬프트를 다시 전달해 기존 산출물을 재사용했다. 원본 11개와 임시 결함 입력을 포함한 사본 69개 파일의 목록·해시가 전후 같았고 추가·삭제·변경은 0개였다. 같은 입력의 검사 재실행도 통과했다.
- 별도 빈 템플릿에서는 첫 프롬프트가 질문·근거·운영 규칙 확인을 요청하며 중단했다. 사본이나 결과 파일을 만들거나 합성 예제로 대체하지 않았다.
- 제한된 공개 해설에서 지지되는 설명과 실제 DRAM 효과·지연 측정 주장에 필요한 근거를 구분했다. 원논문 대조, 장치 측정, 계획 채택은 미실행·사람 판단으로 남겼다. 특정 모델이나 모든 프로젝트에서 같은 결과를 보장하는 시험은 아니다.
