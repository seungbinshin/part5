01 / 04원강의역할을 늘리기 전에 경계를 정합니다

무슨 일을, 어디까지
맡길 것인가

Part 4까지 완성한 AI Wiki에 역할과 인계 규칙을 더합니다. 기존 논문 읽기·실험 로그 Skill의 절차 문서를 재사용하고 맡길 일과 멈출 조건을 정합니다.

에는 반복할 절차를, 에는 임무와 책임 범위를 담습니다. 문헌 검토 역할이 논문 읽기 Skill을 사용하는 식으로 연결합니다.

선수 조건: Part 4의 AI Wiki와 논문 읽기·실험 로그 절차 문서를 이어 씁니다. Skill 등록·호출 상태는 사용 도구에서 따로 확인합니다. 설치와 Wiki 만들기는 반복하지 않습니다. 필요한 부분만 Part 4 자료에서 확인하세요.

네 역할의 차이

이름보다 입력과 출력이 중요합니다. 앞 단계의 제안을 다음 단계가 확정된 결과로 받아들이지 않도록 경계를 남깁니다.

역할받는 자료 → 돌려줄 것여기서 멈춥니다
문헌 검토

실험 계획
Experiment Planner		질문·기록·제약 → 후보 비교와 순위가 바뀔 조건실험 실행·결과 수치 생성·채택을 하지 않음
초안 작성

초안 검토

위임 요청에 다섯 칸을 둡니다

목표 · 입력

확인할 질문과 자료를 지정합니다

“논문을 검토해 줘”보다 “원고 v1의 주장 세 개가 근거 대장의 범위 안에 있는지 검토해 줘”가 명확합니다.

제약 · 출력 · 중지

변경 범위와 끝을 정합니다

새 실습 예제에서 원고는 읽기만 하고 지적은 세 건 이내로 반환합니다. 원본이 없으면 그 위치를 적고 확인을 요청합니다.

적용 판단

한두 문장 수정처럼 대화가 그대로 이어지는 일은 메인 에이전트에서 처리해도 됩니다. 따로 읽을 자료가 많고 결과를 짧게 돌려받을 수 있을 때 역할 분리를 검토하세요.

현대적 보완 · 네 역할을 꼭 네 자율 에이전트로 만들어야 할까요?

저자 설계 권고 · 2024 Anthropic은 정해진 경로를 따르는 와 모델이 다음 행동을 정하는 에이전트를 구분하고 단순한 방식부터 시작하라고 권합니다.

수업 적용 자료가 고정돼 있다면 한 모델의 단계별 호출부터 비교하세요. 새 자료를 찾으며 조사 방향을 바꿔야 할 때 필요한 단계에 자율 탐색을 더할 수 있습니다.

Building effective agents · 2024-12-19. 구조 원칙을 읽는 자료이며 2026년 기능 안내가 아닙니다. 확인 2026-10-26.

심화 · 역할이 많아지면 생기는 비용

역할마다 입력을 전달하고 산출물을 확인해야 합니다. 이름만 다른 역할을 늘리면 같은 자료를 중복해서 읽거나 서로 다른 가정으로 작업할 수 있습니다. 네 역할과 다섯 리뷰어는 원강의의 예시 구성입니다. 모든 연구에서 아홉 역할이 필요한 것은 아닙니다.

편집 판단 필수 실습은 기존 Wiki의 질문 하나와 주장 세 개 이내를 다룹니다. 기존 Skill을 재사용해 근거·계획·초안·검토·인계를 연결하며 긴 실행은 요구하지 않습니다.

문헌에서 찾은 주장, 앞으로 할 실험, 이미 측정한 결과는 서로 다릅니다. 다음 역할이 이 차이를 읽을 수 있어야 합니다.

문헌 검토원문 위치·상태
실험 계획비교·미확인 조건
초안 작성본문·근거 대장
초안 검토대조·연구자 결정

계획은 순위의 이유를 돌려줍니다

실험 후보를 근거·실행 가능성·비용·로 비교합니다. 네 축의 점수를 합산하지 않습니다. 순위를 가른 근거와 순위가 바뀔 조건을 남깁니다.

기록이 없는 비용이나 평가 조건은 “확인 필요”로 둡니다. 후보표를 초안 재료로 쓰기로 한 승인과 실제 실험을 실행하라는 승인은 별개입니다.

초안보다 근거 대장을 먼저 만듭니다

에는 값뿐 아니라 원본 위치, 평가 조건, 아직 확인하지 못한 항목을 적습니다. 초안은 그 범위 안에서 씁니다.

작성자의 확인

빠진 근거를 드러냅니다

본문과 대장의 숫자, 인용, 비교 조건이 맞는지 확인합니다. 형식이 맞아도 논리가 타당한지는 별도 검토가 필요합니다.

검토자의 확인

원본까지 되짚습니다

본문 → 근거 대장 → 원본을 대조합니다. 같은 모델에게 같은 답을 다시 만들게 하는 것은 원문 검증을 대신하지 못합니다.

적용 판단

“주장이 맞다”보다 “어느 자료의 어떤 조건까지 지지되는가”를 먼저 물어보세요. 검토자는 근거의 빈칸과 수정 방향을 남기고 채택과 수정은 연구자가 결정합니다.

심화 · 원강의의 숫자를 읽는 법

강의에 나온 초안 분량과 지적 건수는 시연 결과입니다. Ch02-04는 해당 초안이 데모용 합성 데이터에 기반했다고 설명합니다. 이 교재에서 실제 연구 성과나 에이전트의 일반 성능으로 사용하지 않습니다.

원고 분량 25,000자와 섹션 규칙도 강의 예제의 계약입니다. 투고처의 실제 요구사항을 대신하는 기준은 아닙니다.

자료 차이 · 비용 추정과 원고 쓰기 권한

강의는 비용을 추정할 때 계산 근거를 붙이라고 설명하지만, 제공된 Planner 정의는 근거가 없으면 산정 불가로 남기도록 더 엄격합니다. 이 교재의 작은 실습은 입력에 없는 비용을 만들지 않습니다.

강의는 Reviewer의 원고 쓰기를 도구 수준에서 막았다고 설명합니다. 그러나 제공 정의에는 Write·Edit가 있고 경로 제한은 본문 지시로 적혀 있습니다. 그 파일만으로 기계적 차단을 검증했다고 말할 수 없습니다. 지시와 실제 권한의 차이를 함께 확인하세요.

03 / 04원강의

함께 일할수록
인계와 충돌을 남깁니다

결과를 여러 개 받는 것만으로 협업이 끝나지는 않습니다. 누가 공용 파일을 고칠지, 의견이 다르면 누가 판단할지 정해야 합니다.

공용 파일은 한곳에서 갱신합니다

서로 다른 결과가 필요한 작업은 병렬로 진행할 수 있습니다. 같은 원고·index·log를 함께 고치거나 앞 단계 결과가 필요한 작업은 순서를 조율합니다.

리뷰어는 각자 검토 결과를 반환하고, 메인이 종합과 공용 기록을 맡습니다. 이 역할 분담은 충돌을 줄이려는 규칙이며 파일 권한 자체를 설정한 것은 아닙니다.

다섯 관점, 같은 원고

원강의는 방법론·공정성·도메인·새로움·표현 관점의 리뷰어를 둡니다. 같은 원고 버전과 허용 자료를 주고, 서로의 리뷰를 먼저 읽지 않도록 를 설계합니다.

비슷한 답 = 실패?

독립적으로 같은 문제를 찾을 수도 있습니다. 결과의 유사성보다 실제 입력과 다른 리뷰의 열람 기록을 확인합니다.

다른 답 = 성공?

편집 판단 다른 결론도 같은 잘못된 가정에서 나올 수 있습니다. 각 지적을 원문 위치와 근거에 연결해 살펴봅니다.

종합할 때 세 부류를 남깁니다

분류남겨야 할 것연구자의 다음 판단
겹치는 지적각 리뷰가 가리킨 위치와 근거같은 문제인지 확인하고 우선순위 결정
충돌하는 지적상반된 해석과 성립 조건추가 자료 확인·문구 축소·실험 보완 중 선택
한 명만 찾은 지적소수 의견의 근거와 놓치면 생길 문제다수결로 지우지 않고 확인
심화 · 끝내지 못했을 때도 인계합니다

에는 작업 ID, 읽은 자료, 산출물 위치, 실제 변경, 제안, 미완료·충돌, 연구자 결정 항목을 적습니다. 경로가 없으면 경로를 물어보고, 근거가 없으면 그 빈칸을 보고합니다.

강의에서도 원고 경로를 생략한 위임이 멈춘 뒤 실제 경로를 넣어 재요청하는 장면이 나옵니다. 대상과 버전을 미리 지정하면 이런 대기를 줄이는 데 도움이 됩니다.

저자 설계 권고 · 2025 컨텍스트 엔지니어링은 지시뿐 아니라 도구 결과와 외부 자료까지 선별하는 일입니다. 수업 적용 인계 요약에 원문 경로와 버전을 남기면 다음 역할이 필요한 근거를 다시 열어볼 수 있습니다. Anthropic · 2025-09-29 · 확인 2026-10-26.

04 / 04현대적 보완공식 문서 확인 · 2026-10-26

역할 이름만으로
보장되지 않는 것들

원강의의 설계 원칙은 유용합니다. 실제 도구에 적용할 때는 컨텍스트, 권한, 비용, 검증을 한 번 더 구분해야 합니다.

1. 분리된 대화와 공유된 파일

Claude Code의 일반 Subagent는 새 에서 시작하지만 fork처럼 대화를 상속하는 방식도 있습니다. 규칙·Skill의 전달은 종류와 설정에 따라 달라집니다. “아무것도 공유되지 않는다”는 설명을 모든 방식에 적용하지 마세요.

적용: 필요한 규칙과 파일을 위임에 적고, 결과에 실제 읽은 자료를 반환하게 합니다. Claude Code 공식 문서 · 시작 컨텍스트

2. 금지 문구와 실제 권한

“원고를 수정하지 마세요”는 행동 지시입니다. 읽기 도구만 허용하거나 실행환경의 쓰기 권한을 제한하는 조치와 구분해야 합니다. 이 교재의 선택 리뷰어는 Read·Grep·Glob만 지정합니다. Anthropic의 2026년 설명도 모델의 판단과 별도로 실행환경의 권한을 제한하는 접근을 다룹니다.

적용: 도구 목록·권한 설정·실제 변경 파일을 따로 확인합니다. 본문의 경로 금지만으로 차단을 증명하지 않습니다. Claude Code 공식 문서 · 도구와 권한 · 제품 보안 설계 · 2026-05-25

3. 병렬화의 이득과 비용

Anthropic의 2025년 연구 시스템 회고는 독립적인 여러 방향을 탐색할 때의 이점과 토큰 비용·조율 문제를 함께 보고합니다. 다른 작업의 결과에 촘촘히 의존하는 흐름에는 같은 이점을 기대하기 어렵습니다.

적용 판단 먼저 한 역할의 품질을 확인하고, 분리할 이유가 있는 작업부터 늘립니다. 이 강의의 시간·비용 개선율은 측정하지 않았습니다. Anthropic · 2025-06-13

4. 여러 답의 합의도 다시 확인합니다

MAST 연구는 다중 에이전트의 실패를 시스템 설계, 에이전트 간 불일치, 과업 검증 문제로 분류합니다. 검토 역할을 추가하면 자동으로 해결된다는 결과는 아닙니다. 여러 역할이 동의해도 원자료를 대조해야 합니다.

적용 판단 결론을 합치기 전에 근거 위치, 충돌, 한 명만 발견한 지적을 보존합니다. 이 원칙을 해당 연구가 모든 연구 심사에 대해 검증했다고 해석하지 않습니다. MAST 논문 · 2025-03-17 / v3 2025-10-26
