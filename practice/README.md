# 기존 Wiki에서 주장 3개를 검토하고 원고는 보존하기

Part 4에서 만든 Wiki의 복사본에 이어서 하는 실습입니다. 먼저 [추가·복구 안내](UPGRADE.md)에 따라 기존 규칙과 두 Skill을 확인하고 `llm_wiki/research/part5-lab/`만 추가합니다. 새 Wiki를 만들거나 Part 4의 준비 과정을 반복하지 않습니다. 아래 명령은 복사본의 `part5-lab/` 안에서 실행합니다.

이 실습은 Part 5의 **작성과 검토를 나누기**, **주장마다 근거를 대조하기**, **연구자가 채택 여부를 결정하기**를 작은 자료로 연습합니다. 모든 초안·근거·숫자는 교육용으로 만든 합성 자료입니다. 실제 논문이나 실험 결과를 재현하지 않습니다.

학습 예산은 약 10분으로 잡았습니다. 수업 시간 실측값은 아닙니다. 기본 경로에는 모델·네트워크 호출이 없고 API 비용도 없습니다. 파일을 열 수 있는 편집기와 Python 3.8 이상만 있으면 됩니다. Python이 없다면 1~3단계를 하고 `expected-review.json`과 직접 대조해도 됩니다.

## 1. 입력과 역할을 확인합니다

먼저 [역할 계약](role-contracts.md)에서 기존 `paper-reading`·`experiment-log`와 네 역할이 이어지는 지점을 봅니다. `manuscript.txt`에는 C1~C3의 짧은 초안, `case-data.json`에는 E1~E2의 근거 대장이 있습니다. 대장이 연결한 `source-results.csv`와 `source-notes.txt`까지 열어 값과 조건을 확인합니다. 입력 파일은 읽기만 합니다. 보고서는 `outputs/review.json`에만 저장합니다. 리뷰어는 수정 방향을 제안하고 연구자는 그중 반영할 항목을 선택합니다.

| 읽을 것 | 확인할 것 |
|---|---|
| `manuscript.txt` | 주장이 어느 범위까지 말하는가 |
| `case-data.json` | 근거가 다루는 조건과 없는 정보가 무엇인가 |
| `source-results.csv`, `source-notes.txt` | 대장의 값·조건이 원본과 같은가 |
| `review-template.json` | 결과 형식, 허용 경로, 승인 대기 상태가 무엇인가 |

## 2. 세 주장에 판정을 붙입니다

`review-template.json`을 복사해 `outputs/review.json`으로 저장하세요. 이 폴더 안에서 처음 시작할 때의 예시는 다음과 같습니다. 이미 보고서가 있다면 덮어쓰지 말고 그 파일을 계속 편집합니다.

```sh
mkdir -p outputs
cp -n review-template.json outputs/review.json
```

각 `classification`에 아래 값 하나를 적고, `reason`과 `next_check`를 채웁니다.

| 판정 | 의미 |
|---|---|
| `supported_within_scope` | 자료가 설명한 조건 안에서는 주장을 지지함 |
| `unsupported_generalization` | 주장이 자료의 조건보다 넓게 일반화함 |
| `insufficient_evidence` | 판단에 필요한 자료가 없음 |

근거가 부족하다는 이유만으로 주장이 거짓이라고 단정하지 마세요. 원고의 대체 문장은 쓰지 않고 무엇을 확인하거나 어느 범위로 좁힐지를 적습니다. `approval_status`는 `awaiting-human`으로 둡니다.

## 3. 형식과 경계를 검사합니다

```sh
python3 check_review.py outputs/review.json
```

정상 출력의 첫 줄은 다음과 같습니다.

```text
PASS: 교육용 판정 3개, 근거 ID, 보고한 쓰기 범위, 입력 파일 무결성
```

검사기는 이 작은 문제의 판정 기준·근거 ID·필수 항목·입력 해시를 확인합니다. 이유의 의미를 이해하거나 실제 연구의 정확성을 평가하지 않습니다. `requested_writes`의 선언을 검사할 뿐 파일 쓰기를 차단하는 보안 장치도 아닙니다.

`expected-review.json`은 미리 작성한 해설입니다. 실제 모델 실행 결과가 아닙니다. 본인 답을 작성한 뒤 비교하세요. 준비된 해설 자체가 검사되는지도 확인할 수 있습니다.

```sh
python3 check_review.py expected-review.json
```

## 4. 사람이 결정하고 마칩니다

각 지적이 원문의 조건을 정확히 짚었는지 읽고 [인계 양식](HANDOFF.md)에 결과를 기록합니다. C2의 범위를 좁힐지, C3의 추가 측정을 별도로 승인할지 선택합니다. 이 실습에서는 원고를 고치거나 실험을 실행할 필요가 없습니다. 보고서를 만들었다는 사실과 연구자가 수정을 승인했다는 사실을 구분하면 완료입니다. 기존 Wiki의 공용 파일에 반영할지는 별도로 결정하고 승인 후 Main 한 명이 기존 갱신 규칙을 따릅니다.

모델에 실제로 맡겨 보고 싶다면 [선택 위임 요청](optional-agent-prompt.md)을 사용하세요. 이미 사용하는 모델에 한 번만 요청해 사람의 결과와 비교하는 선택 확장입니다. 이 교재 제작 시 실제 모델 호출은 하지 않았습니다.

## 막히면

| 표시 또는 상황 | 해결 |
|---|---|
| `python3`를 찾지 못함 | 편집기에서 파일을 읽고 해설과 수동 비교합니다. 설치는 필수 경로가 아닙니다. |
| JSON을 읽을 수 없음 | 쉼표·큰따옴표·괄호를 확인합니다. 코드 블록의 백틱은 JSON 파일에 넣지 않습니다. |
| 교육용 판정 기준과 다름 | C1은 조건 한정, C2는 일반화 범위, C3은 측정 누락을 다시 봅니다. |
| 역할 계약과 다른 값 | 쓰기 경로는 `outputs/review.json`, 원고 변경은 `false`, 최종 결정은 승인 대기인지 확인합니다. |
| 입력 파일이 없거나 바뀜 | 원본 배포본에서 해당 입력만 비교·복구합니다. 본인 보고서는 보존합니다. |

## 정리·복구

이 실습은 서비스·계정·에이전트 설정을 만들지 않습니다. 끝나면 보고서를 보관하거나 `outputs/review.json`만 편집기에서 삭제하세요. 다시 시작하려면 보고서 사본을 보관한 뒤 템플릿으로 새 보고서를 만듭니다. 입력 파일과 `input-checksums.json`은 원본대로 둡니다.
